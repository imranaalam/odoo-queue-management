🧑‍🤝‍🧑 Queue Management

Universal queue system for Odoo — works for clinics, banks, counters, and any service desk. No POS required.


Odoo 17 Standalone App REST API SMS / WhatsApp Live Board

Features

📋 Multiple Named Queues

Create as many queues as you need — "Cashier", "Doctor", "VIP Counter" — each with its own prefix, colour, and settings.

🎫 Token Lifecycle

Waiting → Called → Serving → Done / Skipped / No-Show. Full state machine with timestamps at every transition.

📺 Live Board

Kanban view grouped by state shows all active tokens at a glance. Call and Done buttons on every card — no form needed.

📢 Call Next / Call Specific

One-click Call Next from the queue form. Or call any specific token by clicking its row. Auto-next mode calls automatically on Done.

📱 SMS & WhatsApp Webhooks

Per-queue POST webhooks fire when a token is called — integrate with any SMS or WhatsApp gateway that accepts HTTP.

📺 External Display Webhook

Push all state changes to a TV display, kiosk, or custom board via a configurable display webhook URL.

🔗 REST API

Full HTTP REST API for external kiosks and digital signage: get status, issue tokens, call next, mark done — all via JSON.

🤝 Partner Integration

Automatically creates or matches a res.partner from the customer name and phone, keeping your contact book tidy.

How It Works

1

Create a Queue

Go to Queue Management → Queues and create a queue — set the name, prefix (e.g. "A"), and optional webhook URLs. A default "Main Queue" is ready on install.

2

Issue a Token

Open the queue form → Tokens tab → Add a row, or use the REST API / another module (e.g. website, POS) to create tokens programmatically.

3

Manage from Live Board

Click Live Board in the menu to see all active tokens in a Kanban. Call, Done, Skip directly from the card.

4

Notifications Fire Automatically

When a token is called, the SMS and WhatsApp webhooks fire — your gateway sends the customer a message. The display webhook updates your TV screen.

REST API Reference

MethodEndpointDescription
GET /queue-management/api/v1/queue/{id} Get current queue status (state, waiting, current token)
POST /queue-management/api/v1/queue/{id}/token Issue a new token. Body: { "name": "Ali", "phone": "+971…" }
POST /queue-management/api/v1/queue/{id}/call_next Call the next waiting token
POST /queue-management/api/v1/token/{id}/call Call a specific token
POST /queue-management/api/v1/token/{id}/done Mark a token as Done
POST /queue-management/api/v1/token/{id}/skip Mark a token as Skipped
POST /queue-management/api/v1/token/{id}/reset Reset a skipped/no-show token to Waiting

How It Differs from POS Queue Management

queue_management (this module)

Standalone — no dependency on Point of Sale. Works for any department: clinics, banks, service desks. Has a REST API for external kiosks.

pos_queue_management (companion module)

POS-specific connector. Adds a Queue button to the POS screen, prints queue slips on the receipt printer, and links queue tokens to POS orders.
